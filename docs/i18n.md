# Páginas e i18n

Inglés y español. Astro arma las URLs. El copy vive en TypeScript, sin paquete i18n externo.

Los dos idiomas llevan prefijo: `/en` y `/es`. `/` redirige a `/en`.

Para arrancar un sitio desde esta plantilla, los pasos están en [setup.md](./setup.md). La intro de la home está en [preloader.md](./preloader.md).

---

## Modelo mental

| Capa | Dónde | Responsabilidad |
| ---- | ----- | --------------- |
| Rutas | `src/pages/[lang]/` | Un archivo por página. `getStaticPaths` recorre `LOCALES` |
| Secciones | `src/pages/_page/` | UI de esa página. La carpeta `_` no genera URL. Reciben `lang` |
| Reutilizables | `src/components/` | Chrome o piezas que usan dos páginas o más. Header, botón |
| Copy | `src/i18n/translations/{en,es}.ts` | Strings por namespace |
| Locales | `src/i18n/locales.ts` | Lista y default. `astro.config.mjs` los importa |
| URLs | `astro:i18n` | `getRelativeLocaleUrl` |

Ejemplo vivo: [`src/pages/[lang]/index.astro`](../src/pages/[lang]/index.astro) monta [`src/pages/_home/preloader/Preloader.astro`](../src/pages/_home/preloader/Preloader.astro), [`src/pages/_home/hero/Hero.astro`](../src/pages/_home/hero/Hero.astro) y [`src/pages/_home/steps/HomeSteps.astro`](../src/pages/_home/steps/HomeSteps.astro). El preloader es solo de la home. El header vive en [`src/components/header/`](../src/components/header/) porque también lo usa About.

## Secciones y componentes

Una sección pertenece a una página hasta que otra página la necesita.

```text
src/pages/[lang]/index.astro       pasa lang
src/pages/_home/hero/Hero.astro    sección. useTranslations(lang)
src/pages/_home/hero/Title.astro   pieza de esa sección. Recibe strings, no lang
src/components/header/Header.astro lo usan Home y About. Recibe lang
src/components/button/Button.astro lo usan varias secciones. Recibe text y href
```

La sección traduce y reparte el copy. `Title` no importa i18n. Un botón tampoco: la sección le pasa `text={t.hero.cta}`. Si el mismo `Title` aparece en About, se muda a `src/components/`.

## Locales

[`src/i18n/locales.ts`](../src/i18n/locales.ts):

```ts
export const LOCALES = ['en', 'es'] as const;
export type Locale = (typeof LOCALES)[number];
export const DEFAULT_LOCALE: Locale = 'en';
```

[`astro.config.mjs`](../astro.config.mjs) importa esa lista:

```js
i18n: {
  defaultLocale: DEFAULT_LOCALE,
  locales: [...LOCALES],
  routing: { prefixDefaultLocale: true },
}
```

`DEFAULT_LOCALE` es el destino de `/`. [`src/middleware.ts`](../src/middleware.ts) hace ese 301. Cambiar el default no mueve carpetas: `[lang]` ya cubre todos los locales.

## Translations tipadas

1. `es.ts` es la fuente de tipos: `export type Translations = typeof es`
2. `en.ts` se anota como `Translations`. Si falta una key, TypeScript falla.
3. Cada área de la UI es un namespace: `common`, `home`, y los que agregues (`header`, `about`, …).

```ts
const t = useTranslations(lang);
t.home.titleLine1;
```

Reglas:

- Ningún string de UI hardcodeado en Astro o TS de sección (salvo ids técnicos y `data-anim`).
- Cada sección nueva agrega su namespace en `es.ts` y en `en.ts`.
- La página pasa `lang` a cada sección. El default seguro es `DEFAULT_LOCALE`.

```astro
---
import type { Locale } from '../../i18n/locales';
import { DEFAULT_LOCALE } from '../../i18n/locales';
import { useTranslations } from '../../i18n/utils';

interface Props {
  lang?: Locale;
}

const { lang = DEFAULT_LOCALE } = Astro.props;
const t = useTranslations(lang);
---
```

Para sumar un idioma: agrégalo a `LOCALES`, crea `src/i18n/translations/{locale}.ts` tipado contra `Translations` y regístralo en `utils.ts`. No hace falta otra carpeta de páginas.

## URLs

Links a una página conocida, con `getRelativeLocaleUrl` de `astro:i18n`:

```ts
import { getRelativeLocaleUrl } from 'astro:i18n';

getRelativeLocaleUrl(lang, 'about');
// en → /en/about
// es → /es/about
```

Sin segundo argumento, apunta a la home de ese idioma (`/en` o `/es`).

El cambio de idioma de la URL actual usa [`getAlternateLocaleUrl`](../src/i18n/utils.ts). Hace falta porque `getRelativeLocaleUrl` no quita un prefijo que ya esté en el path.

Una URL sin idioma (`/about`) no existe.

## Checklist de una página nueva

- [ ] Secciones en `src/pages/_page/`, reciben `lang`
- [ ] Piezas de esa sección al lado, reciben strings ya traducidos
- [ ] `src/components/` solo si lo usan dos páginas, o es chrome (header, botón)
- [ ] Un solo `src/pages/[lang]/page-name.astro` con `getStaticPaths` sobre `LOCALES`
- [ ] `const { lang } = Astro.params` y el mismo componente para todos los idiomas
- [ ] Namespace en `es.ts` y `en.ts`
- [ ] Links internos con `getRelativeLocaleUrl`
- [ ] `<html lang>` sale del layout, no de un string fijo
